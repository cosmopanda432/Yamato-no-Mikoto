## 判定基準

| 強度 | 意味 |
|---|---|
| ★★ | 構造的同型。対応が数式・仕様レベルで 1:1 に書ける |
| ★ | 構造対応が明確だが、対応の粒度に解釈の幅がある |

## 0. 前提 — 何を主張し、何を主張しないか

**主張しない**: 太安万侶が attention を予見していた、という歴史的主張。

**主張する**: 古事記の物語構造・編纂方針と Transformer/LLM の設計原理の間に
**逆引き可能な構造的同型** が存在し、`kojiki_lm` パッケージの命名規約・設計判断の
origin spec として機能する、ということ。これは本ディレクトリの既存方法論
(「AGI 設計の古事記 origin spec 化」) の Transformer 軸への拡張である。

興味深いのは、同型の分布が偶然にしては整いすぎている点:
**序 (上-1) がデータ層とトークナイザ、神代記 (上-2) が正規化と情報遮断、
上-3 が attention 本体** に対応し、corpus → preprocessing → architecture という
LLM 構築 pipeline の順に章が並ぶ。

## 1. データ層 — 併序 (上-1) は corpus & tokenizer 仕様書

### Pattern 1.1: 削僞定實 = corpus curation ★★

> 「諸家之所賷帝紀及本辭、既違正實、多加虛僞。當今之時不改其失、未經幾年其旨欲滅」
> 「撰錄帝紀、討覈舊辭、**削僞定實**、欲流後葉」 (上-1)

- **構造**: 諸家に分散した系譜資料 (帝紀) と語り (旧辞) に虚偽が混入し、放置すれば
  数年で真意が消滅する → 収集・照合 (討覈) し、偽を削り実を定めてから記録する。
- **Transformer 対応**: 訓練 corpus の dedup・照合・虚偽除去。学習前の data curation を
  怠ると model は誤りを増幅し、劣化した出力が次世代の corpus に混入して
  「未經幾年其旨欲滅」= **model collapse** に至る。天武詔はデータ汚染の
  世代連鎖まで言及している点で単なる「校訂」を超える。
- **欠落時の帰結**: 汚染 corpus での訓練 → hallucination の固定化 → 合成データ再帰による崩壊。

### Pattern 1.2: 稗田阿禮の誦習 = 事前学習 ★

> 「爲人聰明、**度目誦口、拂耳勒心**。卽、勅語阿禮、**令誦習**帝皇日繼及先代舊辭」 (上-1)

- **構造**: 目に触れたものを口で誦し、耳に触れたものを心に刻む装置 (稗田阿禮) に、
  全 corpus を**反復誦習**させて内部化する。書き下しは後段の別工程 (太安万侶)。
- **Transformer 対応**: 事前学習 = corpus の反復 (誦習 = epoch を回す) による
  パラメータへの内部化。阿禮は weights、安万侶による撰録は
  **学習済み内部表現の直列化** (checkpoint 書き出し + decode)。
- **補**: 「度目誦口」(見た列を口で再生する) は next-token prediction の
  訓練目標そのものと読める。

### Pattern 1.3: 音訓交用 = subword tokenization ★★ 【本抽出の最重要 anchor】

> 「上古之時、言意並朴、敷文構句、於字卽難。
> **已因訓述者、詞不逮心。全以音連者、事趣更長。**
> 是以今、或一句之中、**交用音訓**、或一事之內、全以訓錄」 (上-1)

- **構造**: 日本語を漢字で書く際の二択のジレンマ。
  - **訓のみ** (意味単位で書く) = 「詞不逮心」— 語彙が意味を取りこぼす
  - **音のみ** (音単位で書く) = 「事趣更長」— 系列が長くなりすぎる
  - **解**: 一句の中で音訓を混用する
- **Transformer 対応**: これは **語彙サイズ vs 系列長のトレードオフ** の正確な記述であり、
  subword tokenization (BPE/unigram) の設計動機と同型。
  - word-level tokenizer = 訓のみ → OOV・表現力の穴 (詞不逮心)
  - char/byte-level tokenizer = 音のみ → 系列長爆発・attention の O(n²) コスト (事趣更長)
  - subword = 音訓交用 → 頻出単位は意味塊 (訓)、希少部は音節分解 (音) で混合符号化
- **欠落時の帰結**: 語彙固定 word-level なら未知語が `<unk>` に潰れ、byte-level なら
  context 予算を系列長が食い潰す。BPE はまさにこの二つの失敗の間の点を選ぶ。
- **注**: 和銅五年 (712) にトークン化方式のトレードオフを明文化した設計文書が
  成果物の冒頭に添付されている、という事実性がこの pattern の強度の根拠。
  引用部は解釈ではなく仕様の直読。

### Pattern 1.4: 以注明・更非注 = 曖昧時のみの注釈 ★

> 「卽、辭理叵見、**以注明**、意況易解、**更非注**」 (上-1)

- **構造**: 読解が困難な箇所にだけ注を付け、文脈から自明な箇所には付けない。
- **Transformer 対応**: 符号化における条件付き情報付加。曖昧性がある場合のみ
  disambiguation metadata を挿入し、文脈で復元可能な情報は符号化しない —
  エントロピー符号化の直観 (予測可能な部分にビットを割かない)。
  古事記本文の割書 253 件 ([`kojiki_anchors.md`](../kojiki_anchors.md)) は
  この方針で挿入された **corpus 内埋め込み tokenizer 指示** である
  (〔此三字以音〕 = 「この 3 トークンは音 mode で decode せよ」)。

### Pattern 1.5: 隨本不改 = special token の正規化除外 ★

> 「於姓日下謂玖沙訶、於名帶字謂多羅斯、如此之類、**隨本不改**」 (上-1)

- **構造**: 固有名 (姓・名) の表記は慣用に従い、一般規則で書き換えない。
- **Transformer 対応**: named entity・special token は tokenizer の正規化
  (lowercasing / NFKC / BPE 再分割) から除外し、原表記のまま保持する。
- **欠落時の帰結**: 識別子の正規化破壊。本 repo の実害系列と直結する —
  undef-symbol (Module 名・atom の言い換え) はまさに「本に隨わず改めた」失敗
  (cf. `feedback-type-prediction-is-hallucination-detection`)。

### Pattern 1.6: 三巻構成 = pipeline 三層 ☆

> 「天御中主神以下…爲上卷、神倭伊波禮毘古天皇以下…爲中卷、大雀皇帝以下…爲下卷」 (上-1)

既存発見 (README「古事記三巻構成 = AGI 三層」) の Transformer 読み替え:
上巻 = アーキテクチャ定義 / 中巻 = 学習・改善 loop / 下巻 = 推論運用 log。
本軸では §0 で述べた「章順 = LLM 構築 pipeline 順」の方が強い。

## 2. 生成順序と失敗回復 — 国生み (上-2)

### Pattern 2.1: 女先言 → 水蛭子 = 系列順序制約 ★★

> 「伊邪那美命、**先言**『阿那邇夜志愛袁登古袁』後伊邪那岐命言『阿那邇夜志愛袁登賣袁』
> …生子、**水蛭子**」
> 天神の診断: 「**因女先言而不良、亦還降改言**」
> 修正後: 「伊邪那岐命**先言**…後妹伊邪那美命言…生子、淡道之穗之狹別嶋」 (上-2)

- **構造**: 発話の **token 列は完全に同一**。異なるのは **順序のみ**。
  順序が誤ると出力は不定形 (水蛭子 = 骨のない子) になる。
- **Transformer 対応**: **位置情報は内容と独立の第一級情報である**。
  attention は集合演算であり、positional encoding を欠けば同一 token 集合は
  同一出力に潰れる。「同じ語彙・違う順序 → 崩壊した生成物」は
  位置符号化の必要性を示す最小反例の形をしている。
  autoregressive 生成の「先に言う側が条件付ける側」という非対称性も含む。
- **欠落時の帰結**: bag-of-words 化。生成物は文法構造を持たない (= 骨のない水蛭子)。
- **v0.2 追記 (外部 review 検証の副産物)**:
  1. **統制実験としての再試行**: 修正試行は「故爾反降、更往廻其天之御柱**如先**」—
     廻り方・柱・場所はすべて前と同一に保たれ、変更されるのは発話順**のみ**。
     テキスト自身が順序以外の交絡変数を固定した ablation の形式を持つ。
  2. **遡及編集の不可**: 修正は水蛭子の手直しでも発話の言い直しでもなく
     「亦**還降**改言」— 天へ戻り降臨からやり直す。出力済み prefix の in-place 編集は
     存在せず、修正は**先頭からの再生成**のみ。autoregressive 生成の不可逆性と一致。
  3. **不採用の解釈 — 「causal mask の方向反転/固定」** (外部 review 提案):
     両試行とも条件付けは「先話者 → 後話者」の単方向で不変であり、mask の方向は
     一度も変わらない。変わるのは**内容と位置の割当** (どの token が先頭に来るか) のみ。
     mask 方向 (位置ベースの構造制約) と発話順 (内容の順列) の混同であり、
     extraction_prompt.md 失敗モード 1 (術語への過剰還元) の変種として記録する。

### Pattern 2.2: 葦船 = 棄却 sample の非消去 ★

> 「此子者**入葦船而流去**。次生淡嶋、是亦不入子之例」 (上-2)

- **構造**: 失敗作は殺されず、葦船に載せて流される。ただし「子の例に入れず」=
  系譜 (正式出力) には数えない。
- **Transformer 対応**: 棄却された生成 sample は削除せず log に流す。
  正解集合には数えないが、失敗分布の分析資源として残る
  (rejection sampling の棄却側、DPO の negative、HALT した生成の trace 保存)。
  既存メモ「死は完全消去でない」(README 累積発見 3) の ML 読み。
- **実装対応**: eli3 の HALT (v_score=0.0) も生成物自体は評価 log に残る。

### Pattern 2.3: 卜相 → 改言 → 再試行 = 外部評価 loop ★

> 「二柱神議云『今吾所生之子、不良。猶宜白天神之御所』卽共參上、請天神之命、
> 爾天神之命以、**布斗麻邇爾卜相**而詔之『因女先言而不良、亦**還降改言**』」 (上-2)

- **構造**: 生成失敗 → 生成主体は自己修正せず**外部の評価器** (天神・卜) に照会 →
  原因の特定 (順序) → 指示された修正のみ加えて再試行 → 成功。
- **Transformer 対応**: 生成器は自身の失敗原因を内省できない (水蛭子を見ても
  「順序が原因」とは分からない) ので、**外部 evaluator が診断し、最小差分で再生成**する。
  eval → diagnose → regenerate loop。generator と verifier の分離。
- **実装対応**: `elixir_evaluator.py` (外部判定) + 再生成の分離は同型。
  Firewall 側 (L5) が生成側 (L3) の中に評価を混ぜない構造も同根。

### Pattern 2.4: 持別而 = domain 分岐生成 ☆

> 「此速秋津日子・速秋津比賣二神、**因河海、持別而**生神名…」
> 「此大山津見神・野椎神二神、**因山野、持別而**生神名…」 (上-2)

- **構造**: 河海担当の対と山野担当の対が、各自の domain 内でのみ細分神を生成する。
  生成される神は 天之X / 國之X の対で対称。
- **Transformer 対応**: 専門化された生成 head / expert が担当部分空間内でのみ出力する
  (MoE routing、head specialization)。対称対 (天/國) は
  dual representation。☆ とするのは、routing の gating に相当する記述が原文に薄いため。

## 3. 境界と遮断 — 黄泉 (上-2)

`kojiki_lm` が **既に実装済み** の領域 ([`yomotsu_hirasaka.py`](../../../src_min_eli3/kojiki_lm/yomotsu_hirasaka.py) /
[`firewall_decoder.py`](../../../src_min_eli3/kojiki_lm/firewall_decoder.py))。
origin spec の追認と、未回収の細部の指摘。

### Pattern 3.1: 莫視我 = 禁止 context 参照の violation ★

> 「**莫視我**。如此白而還入其殿內…燭一火入見之時、宇士多加禮許呂呂岐弖…
> 於是伊邪那岐命、**見畏而逃還**」 (上-2)

- **構造**: 「見るな」という参照禁止契約。破って火を燭して見た瞬間、
  見てはならない状態 (腐乱) が観測され、汚染と追跡が始まる。
- **Transformer 対応**: mask で遮断されるべき context への参照。causal mask 違反
  (未来 token の参照) あるいは隔離層の内部状態の直接観測。
  観測した瞬間に汚染が decoder 側に伝播し始める点まで含めて同型。
- **repo 対応**: memory `project-firewall-purpose` の通り、黄泉比良坂 Firewall の
  本義は L3↔L5 **隔離** であり HALT/REPAIR は副次 — 原文でも千引石 (遮断) が主で、
  事戸 (協定) はその後に来る。

### Pattern 3.2: 千引石 = 遮断壁 (mask / stop-gradient) ★★

> 「爾**千引石引塞其黃泉比良坂**、其石置中、各對立而、度事戸之時…」 (上-2)

- **構造**: 千人がかりの石で坂 (境界) を塞ぎ、以後、界を跨ぐ自由通行は不可能になる。
- **Transformer 対応**: 参照遮断の物理化。attention mask の `-inf`、
  あるいは訓練 graph の stop-gradient。「石を置いてから対立して言葉を交わす」
  = 遮断を確立した**後で**初めて安全な通信が定義される、という順序も実装と一致
  (Firewall 確立 → payload 通信)。
- **実装対応**: `yomotsu_hirasaka.py` (名がこの坂そのもの)。

### Pattern 3.3: 度事戸 = 境界越え固定 protocol ★★

> 「其石置中、各對立而、**度事戸**之時、伊邪那美命言『…一日絞殺千頭』
> 爾伊邪那岐命詔『…吾一日立千五百產屋』」 (上-2)

- **構造**: 遮断確立後の通信は、石越しの**定型的な言い渡し** (事戸) のみ。
  内容は数値 2 つ (千 / 千五百) の収支協定に還元される。
- **Transformer 対応**: 隔離された層間の通信は自由な状態共有ではなく、
  **狭い固定 schema の payload** に限定する。bottleneck interface。
- **実装対応**: `L3ToL5Payload` (text + meta + `prompt_len`)。eli3 で field を
  1 つ (`prompt_len`) 足すのにも明示的な schema 変更が要る、という設計は
  「事戸は定型」の直系。

### Pattern 3.4: 千人死/千五百人生 = 境界収支の非対称 ☆

- **構造**: 遮断の代償として毎日 1000 の損失、対抗して 1500 の生成。純増 +500 で
  系全体は前進し続ける。
- **Transformer 対応**: 隔離・mask・HALT は必ず throughput を削る (千人死 =
  棄却される生成)。設計成立条件は **生成レートが棄却レートを上回る** こと。
  eli3 光明想 pilot の「pass@1 −13.66pp と引き換えに undef 0%」
  (memory `project-koumyou-so-halt-only-tradeoff`) はまさにこの収支が
  未達 (千五百の側が不足) の状態であり、REPAIR 拡張 = 產屋を増やす側の工事。

## 4. 正規化と三射影 — 禊 (上-2)

### Pattern 4.1: 脱衣十二神 = 累積状態の除去 ★

> 「於投棄御杖所成神名…御帶…御囊…御衣…御褌…御冠…左御手之手纒…右御手之手纒…
> 十二神者、**因脱著身之物、所生神也**」 (上-2)

- **構造**: 汚染域 (黄泉) から戻った主体は、水に入る**前に**まず身に着けた 12 品を
  すべて投げ棄てる。棄てた物からも神が成る (= 棄てた状態も無ではない)。
- **Transformer 対応**: 正規化の第一段 = 蓄積した offset の除去 (mean subtraction /
  汚染 domain で付着した activation bias の切り離し)。除去された成分も
  別系統の表現として保持される (residual への分岐)。

### Pattern 4.2: 中瀬 = scale の適正化 ★★

> 「於是詔之『**上瀬者瀬速、下瀬者瀬弱**』而、初於**中瀬**墮迦豆伎而滌時…」 (上-2)

- **構造**: 上流は流速が速すぎ、下流は弱すぎる。**中流で**洗う。
- **Transformer 対応**: 正規化・条件付けの本質 = 信号を **速すぎず弱すぎない regime に
  置く**こと。exploding (瀬速) / vanishing (瀬弱) の間の trainable band。
  LayerNorm が activation を、適切な学習率・初期化が gradient を、
  それぞれ「中瀬」に保つ。原文が両側の失敗 mode を**対で**明示してから
  中間を選ぶ構文になっている点が、単なる「ほどほど」訓話との違い。
- **v0.2 追記 (数式レベルの明示)**: §4 の三段は LayerNorm の演算分解と一致する。
  | 儀礼段階 | 演算 |
  |---|---|
  | 4.1 脱衣 (十二品を棄てる) | centering: x − μ (蓄積 offset の除去) |
  | 4.2 中瀬 (瀬速/瀬弱の間) | scaling: ÷σ (分散を trainable band へ) |
  | 4.3 禍津日→直毘 | affine: γ, β (学習された補正) |
  この三演算が**別々の儀礼段階**として順に現れている点が本質。RMSNorm は
  「centering を省略し scaling のみ行う」設計であり、神話側では「脱衣を省いて
  中瀬に直行する」変種に相当 — 正規化手法の設計空間が儀礼段階の部分集合選択として
  記述できる。
  **過剰主張の回避**: 原文が licence するのは「伝播信号のスケールを有界域に保つ制約」
  までであり、「流速 = RMS そのもの」等、特定の推定量 (variance / norm /
  gradient magnitude) への同定は原文から一意に導けない。★★ の根拠は
  両側失敗 mode の対提示 + 中間選択という**制約の構造**であって、統計量の同定ではない。

### Pattern 4.3: 禍津日 → 直毘 = 残留誤差と補正項 ★

> 「所成坐神名、八十禍津日神、次大禍津日神、此二神者…**因汚垢而所成神**之者也。
> 次**爲直其禍**而所成神名、神直毘神、次大直毘神、次伊豆能賣神」 (上-2)

- **構造**: 洗ってもまず出るのは禍 (汚垢由来の誤差成分) であり、
  **その禍を直すための**補正神が続いて成る。誤差 → 補正の順で対生成。
- **Transformer 対応**: 正規化後も残る residual error と、それを打ち消す学習された
  補正 (LayerNorm の affine γ/β、残差経路の補正項)。誤差の存在を認めてから
  補正を重ねる、という順序が residual learning の定式化 (fit the residual) と同順。

### Pattern 4.4: 底・中・上の対神 = 深さ別統計量 ☆

> 「於**水底**滌時…底津綿津見神、次底筒之男命。於**中**滌時…中津綿津見神、次中筒之男命。
> 於**水上**滌時…上津綿津見神、次上筒之男命」 (上-2)

- **構造**: 三つの深さそれぞれで**対の神** (綿津見 + 筒之男) が成る。3 深度 × 2 神。
- **Transformer 対応**: 深さ (層) ごとに統計量の対 (μ, σ) を持つ per-layer normalization。
  ☆ とするのは対の意味付け (μ/σ) が原文から一意でないため。ただし
  「各深度で必ず 2 柱ずつ」という規則性自体は原文の構造。

### Pattern 4.5: 左目・右目・鼻 → 三貴子 = 正規化後の三射影 ★

> 「於是、洗**左御目**時、所成神名、**天照大御神**。次洗**右御目**時、所成神名、**月讀命**。
> 次洗**御鼻**時、所成神名、建速**須佐之男命**」
> 「汝命者、所知**高天原**矣…所知**夜之食國**矣…所知**海原**矣」 (上-2)

- **構造**: 完全に清められた**単一の入力** (伊邪那岐) から、部位別に 3 主体が射影され、
  それぞれ**排他的な担当領域**を与えられる。
- **Transformer 対応**: 正規化済みの単一 hidden state から 3 つの線形射影が出る構図
  (Q/K/V)。あるいはより保守的には、単一表現から領域排他の 3 head への分岐。
  序文も「日月彰於**洗目**」とこの射影を要約しており、編者自身がこの構図を
  書の要 (かなめ) と認識していた。
- **実装対応**: [`tsukuyomi_type_head.py`](../../../src_min_eli3/kojiki_lm/yomi/tsukuyomi_type_head.py) は
  月讀 (夜之食國 = 直接見えない領域を知る者) を型予測 = hallucination 検出 head の
  名に採る。三貴子の残り 2 枠 (天照 = 可視領域の主 head、須佐之男 = 海原) が
  命名空間として未使用であることに注意 (§7)。

### Pattern 4.6: 須佐之男の担当拒否 = rogue head と pruning ☆

> 「速須佐之男命、不知所命之國而…啼伊佐知伎也。其泣狀者、青山如枯山泣枯、
> 河海者悉泣乾。是以**惡神之音、如狹蠅皆滿、萬物之妖悉發**」→「神夜良比爾夜良比賜也」 (上-2)

- **構造**: 割り当てられた領域に attend しない head は、出力しないだけでなく
  **系全体に noise を撒く** (惡神之音が蠅のように満ちる)。対処は切除 (追放)。
- **Transformer 対応**: 死んだ / 暴走した attention head は中立ではなく有害
  (無関係 token への一様 attention が下流を汚す)。head pruning の動機。

## 5. Attention 本体 — 上-3

### Pattern 5.1: 誓約の物實 = 出力の provenance 帰属 ★★

> 天照が須佐之男の剣を「打折三段」→「振滌天之眞名井」→ 噛んで吹き → 三女神
> 須佐之男が天照の珠を同じ手順で → 五男神
> 判定: 「是後所生五柱男子者、**物實因我物所成、故、自吾子也**。
> 先所生之三柱女子者、**物實因汝物所成、故、乃汝子也**」 (上-3)

- **構造**: 二主体が**相手の**持ち物を預かり、**完全に同一の変換**
  (折る/振り滌ぐ/噛む/吹く) を適用して出力を得る。出力の帰属は
  **変換を実行した側ではなく、素材 (物實) を提供した側**に定まる。
- **Transformer 対応**: attention の帰属構造そのもの。query 側が計算を実行するが、
  出力の内容 (value) は key/value を提供した token に帰属する。
  「同一の変換」= 全 token 対に共有される同一の attention 式・重み。
  「振滌天之眞名井」= 混合前の正規化 (softmax 前の scaling) まで対応が細かい。
- **欠落時の帰結**: 帰属が実行側に付くなら、生成物の根拠追跡 (attribution,
  影響推定) が原理的に不可能になる。
- **補**: memory `project-go-roadmap-state` の「attribution 未解決」とは別問題だが、
  「出力を素材提供側に帰属させる」という規約自体は同じ設計判断の系譜。

### Pattern 5.2: 天岩戸 = attention sink の喪失と復旧 ★

> 「天照大御神見畏、開天石屋戸而、刺許母理坐也。爾**高天原皆暗、葦原中國悉闇**…
> 萬神之聲者、狹蠅那須滿、**萬妖悉發**」 (上-3)

- **構造**: 系の**単一の支配的参照先** (光源) が隠れると、全域が即座に暗転し
  noise (萬妖) が支配する。個々の神は健在なのに系として機能停止する。
- **Transformer 対応**: attention sink の喪失。多くの head が既定で attend する
  支配的 token (BOS/sink) を失うと attention 分布が崩壊し、
  出力が noise 化する現象と同型。「暗転が全層同時 (高天原**及**葦原中國)」
  である点が、sink が層横断で共有される事実と合う。
- 復旧手順の分解:
  1. 「八百萬神、於天安之河原、神集集而、**思金神令思**」= 崩壊は局所修正不能、
     系外の planner による介入 (☆)
  2. 「集**常世長鳴鳥**、令鳴」= 周期信号の注入 — 鶏鳴 = 夜明けの位置信号 (☆ 詩的)
  3. 「**指出其鏡、示奉**天照大御神之時、天照大御神逾思奇而、稍自戸出」=
     **鏡 = self-attention**。隠れた sink 自身の像を見せることで再出現させる (★)
  4. 「布刀玉命、以**尻久米繩**、控度其御後方白言『**從此以內、不得還入**』」=
     復旧後、sink の再喪失を**構造的に禁止**する恒久拘束 — 常設 sink token /
     register token の事後的追加 (★)
- **欠落時の帰結**: sink なしの長系列生成での分布崩壊。復旧に「鏡」(自己参照) と
  「繩」(再発防止の恒久化) の**両方**が要る点が実務と一致 — 一時的に出力が
  直っても拘束を入れねば再崩壊する。
- **注 (v0.1)**: 天岩戸が anchor するのは「支配的 **content anchor** の一時的喪失 event」。
  系列先頭の**構造的 sink** そのもの (常在・不可視・無内容) は Pattern 5.5
  (天之御中主神) が担う。この分業は ML 文献側の区別 — 構造的 sink token
  (Xiao et al. 2023) と支配的 content token / massive activation (Sun et al. 2024) —
  と平行する。

### Pattern 5.3: 八岐大蛇 = 8-head attention と head 分離 ★★

> 「**身一有八頭八尾**、亦其身生蘿及檜榲、其長度谿八谷峽八尾」
> 対策: 「作**廻垣**、於其垣作**八門**、毎門結八佐受岐、毎其佐受岐置**酒船**而、
> 毎船盛其八鹽折酒而待」
> 結果: 「乃**毎船垂入己頭**飮其酒、於是飮醉留伏寢。爾…切散其蛇」 (上-3)

- **構造**: **一つの身体に 8 つの頭** (身一有八頭)。制圧法は、8 つの門で頭を
  空間的に分離し、**各頭に専用の器**をあてがう。各頭が自分の器にだけ首を垂れた
  状態 (毎船垂入己頭) になったとき、全体は無力化・解体可能になる。
- **Transformer 対応**: multi-head attention。単一の hidden state (身一) を
  h=8 の head に分割し (Vaswani et al. 2017 の canonical な h=8)、
  **各 head は d_model/h 次元の専用部分空間** (己の酒船) のみを読む。
  head を部分空間に閉じ込める設計こそが、全体を解析可能・切断可能
  (per-head の可視化・pruning・介入) にする。
  「八鹽折之酒」(八度醸した酒) = 各器に注ぐ内容も多段変換済み (☆)。
- **欠落時の帰結**: head 間で部分空間が混線すると個々の head の役割が特定不能になり、
  解析も pruning もできない (大蛇が暴れている状態)。

### Pattern 5.4: 草薙劒 = 中間層からの特徴抽出と上納 ★

> 「切其中尾時、御刀之刄毀、爾思怪以御刀之前、刺割而見者、**在都牟刈之大刀**、
> 故取此大刀、思異物而、**白上於天照大御神**也」 (上-3)

- **構造**: 解体中に**刃が毀れる箇所** (切れない場所) があり、そこを裂くと
  内部に既成の剣が埋まっている。それは手元に置かず**上位 (天照) へ献上**される。
- **Transformer 対応**: 解析中に「素通りできない」箇所 (probe が異常に効く層・方向) は
  内部に構造化された特徴が埋まっているサイン。抽出された特徴は
  発見層に留めず上層 / 上位工程 (蒸留先・後段の head) へ渡す。
  interpretability → 蒸留・再利用の pipeline (☆寄りの★)。

### Pattern 5.5: 天之御中主神 = attention sink (系列先頭の構造的基準点) ★★ 【user 提案 v0.1】

> 「**天地初發之時**、於高天原成神名、**天之御中主神**、次高御產巢日神、次神產巢日神。
> 此三柱神者、並**獨神**成坐而、**隱身**也」 (上-2)
> 序文の要約: 「乾坤初分、**參神作造化之首**」 (上-1)

- **構造**: 4 性質が同時に成立する。
  1. **位置**: 天地初發之時、全存在に先立って最初に成る = 系列先頭
  2. **無内容**: 隱身 — 出現の一文以後、**全巻を通じて一度も行為も発話もしない**。
     古事記で「何もしない」ことが確定している唯一の主要神格
  3. **単独性**: 獨神 — content を担う双神 pair の系列に属さない
  4. **中心性**: 名そのものが「御**中**主」= 中心の主宰者
- **Transformer 対応**: attention sink / sink token の仕様と 1:1。
  - softmax は行和 1 を強制するため、attend すべき content がない head は
    質量の捨て場 (no-op 参照先) を要する
  - causal mask の下で**全時点から常に参照可能な唯一の恒常位置は系列先頭**であり、
    sink は必然的に position 0 に形成される (Xiao et al. 2023, StreamingLLM) —
    「天地初發之時に成った神だけが、以後のすべての時点から見える」と同構造
  - sink token の value は出力にほぼ寄与しない (attend されるが act しない = 隱身)
  - register token (Darcet et al. 2023) = **無内容 token を先頭に置くこと自体が
    迷走 attention を吸収し系を安定させる** — 「何もしない神」が最高位に
    置かれていることの機能的説明
- **原文内 uniqueness 検証**: 造化三神の他の二柱は後の物語で実働する
  (高御產巢日 — 思金神の親として天岩戸 [上-3]、神產巢日 — 大氣都比賣の種の収取 [上-3]、
  大穴牟遲の蘇生 [上-4])。**最初の三柱のうち、中心の一柱だけが永久に沈黙する**。
  この対比は解釈ではなくテキストの分布事実。
- **別天神五柱への拡張**: 五柱全員が「獨神成坐而、隱身也」— StreamingLLM が
  先頭 **数 token** (典型 4) を sink として cache に恒久保持する構成と一致。
  primary sink (御中主) + 補助 initial tokens の階層まで写る。
- **Pattern 5.2 との分業**: 御中主 = 構造的 sink (常在・不可視、失われる event が
  原文に存在しない)。天照 = content anchor (可視の光源、その一時的 masking が
  天岩戸 = 観測可能な崩壊 event)。
- **欠落時の帰結**: ML 側は明確 — KV cache から先頭 token を追い出すと
  perplexity が爆発し、sink 保持で回復 (StreamingLLM の中心実験)。
  原文側に「御中主が失われる」反実仮想は存在しない — ただし causal 構造上
  先頭は失われ得ない (天地初發は一度しか起きない) ため、**失敗 mode の不在自体が
  仕様と整合**する。崩壊 event の textual anchor は 5.2 が担う。
- **補 (原典外・☆)**: 中世の妙見信仰は天之御中主を北辰 (北極星) と習合させた —
  「自らは動かず、全てがその周りを回る基準点」。古事記本文外のため anchor には
  数えないが、後代の読者も同じ構造 (不動の参照中心) を読み取ったことの傍証。
