## 1. 問題定義

LLM の推論は訓練データ = 人間の思考の統計的分布に縛られ、人間の認知バイアス・誤謬・時代的制約を
そのまま再生産する。本軸はこの継承バイアスについて、以下を工学として扱う:

- **分類**: どの種類のバイアスが、どの層 (見解 / 習慣 / 知覚) に住むか
- **計測**: 処理 (推論時の機構) で除去できる範囲と、学習 (重み更新) でしか除去できない範囲の境界の実測
- **除去/封じ込め**: 各層に対応するレバーの選択

前提となる知見: 仏教の煩悩論 (隨眠品) は「継承された認知の歪みの潜伏・伝播・除去」の形式理論であり、
cosmology (事実主張) と違いメタ理論なので文明の発達度に依存しない。ただし対応付けは証拠ではなく、
採用基準は常に「ML 側に独立の裏付けがあり、ablation で殺せる予測を生むか」に置く。

## 3. 三レバー整理 (処理 vs 学習)

バイアス除去のレバーは3本あり、代替関係ではなく役割分担 (伝統側の 戒・慧・修 と同構造):

| レバー | 教義対応 | 工学対応 | 本 repo での所在 |
|---|---|---|---|
| 処理による除去 | 見道 (一度の洞察) | in-context repair / grounded feedback | 產屋 REPAIR loop (eli4) |
| 処理による封じ込め | 戒 (行動への外部制約) | 制約デコーディング。除去でなく出口で塞ぐ (マスクを外せば戻る) | Kotodama mask / Firewall HALT / KoumyouSo |
| 学習による除去 | 修道 (數數習道) | fine-tune / LoRA | **なし** (PEFT は依存のみ、学習アームは未実装) |

本 repo で今日実装可能なのはすべて処理側。仕様Aは「いつ学習側に切り替えるべきか」を教える測定器。

## 4. 仕様A (主): 見所断/修所断 計測 — 処理天井の実測

**目的**: repair ログから「1回の接地で直る誤り (見所断)」と「何度 repair しても再発する誤り (修所断)」を
分類し、処理アプローチの天井を実測する。

- **入力**: eli4 `repair-on` run の葦船ログ (`ashibune.jsonl`)。必要 field は既存のもので足りる
  (prompt_id / round / seed_used / reason_code / test_ok / accepted)。**新規の生成 run は不要** —
  既存ログの事後分析のみで予備検証できる。
- **分類規則 (概要)**:
  - **見所断**: round 0 で fail → round 1 以降の接地フィードバックで pass し、以後再発しない
  - **修所断**: 複数 seed × 全 round を通じて同種の誤り (reason_code / undef-symbol 種別) が再発し続ける
  - 判定は誤り種別 (reason_code 等) 単位で行い、sample 単位の偶発的成功と区別する
- **出力**: 誤り種別ごとの分類表 + 修所断率 (= 全失敗のうち repair で消えない割合) + round 数に対する
  pass 率曲線 (頭打ちの有無)
- **判断規則**: 修所断クラスが主要な失敗要因として残るなら、それが学習アーム (LoRA 等) 追加の
  経験的正当化になる。ほぼ全部が見所断 + 戒で片付くなら、学習アームは不要という結論も同じ測定から出る
- **交絡への注意**: 「1回で直った」は feedback の質・温度・seed に依存する。seed 横断・round 横断の
  再発で定義しないと分類が不安定になる (閾値は実装時に確定)

## 5. 仕様B (副): 継承慣習の metamorphic test

**目的**: 訓練データ由来の慣習 (「X は常にこう書く」) が spurious か機能的かを判別する。

- **方法 (概要)**: prompt の表層特徴 (識別子名・コメント言語・例示の順序など、意味論に無関係な
  継承特徴) を変動させ、生成物の機能 (test_ok / undef-symbol) が不変かを測る。不変でなければ、
  モデルは表層特徴に因果的に依存している = 継承バイアスの検出
- **位置づけ**: 世本縁品・手順2 ([世記経.txt:665](../../data/仏教宇宙論/世記経.txt)) の移植。
  ソフトウェアテストの metamorphic testing として確立済みの手法であり、本 repo への適用が新規な点
- **仕様Aとの関係**: 仕様Aが「repair で直るか」を測るのに対し、仕様Bは「そもそも何に依存して
  生成しているか」を測る。独立に実施可能

## 6. スコープ外

- 学習アーム (LoRA / fine-tune) の実装 — 仕様Aの結果が正当化した場合にのみ検討
- 遍行クラスタリング (原理5) の自動化 — 仕様Aの出力を眺める手動分析で当面十分
- 顛倒三因 (原理4) の metric 化 — 現行の undef-symbol / test 失敗の分離で実質カバー済み
- 世本縁品・手順1 (系譜追跡) と手順3 (出口) — 訓練データに対して運用可能な形にならないため不採用
