## 0. 中心命題 — 報酬軸の argmax は敵対者の座

親 memo Part 1 §1 は三界の垂直軸を「報酬の質的階層」と読んだ。本書の追加発見は
その軸の**欲界内の終端**についての cosmology の主張:

**欲界の最上階に住むのは達成者ではなく魔である。**

> 「四天王天壽五百歲…三十三天，壽一千歲；夜摩諸天，壽二千歲；兜率陀天，壽四千歲；
> 化樂諸天，壽八千歲；他化自在天，壽萬六千歲；**魔身天，壽三萬二千歲**；
> 梵身天，壽命**一劫**」 ([起世経.txt:589](../../data/仏教宇宙論/起世経.txt))

引用 anchor から読める構造は 2 つ:

1. **報酬 (寿量) は各天で正確に倍々** (500 → 1k → 2k → 4k → 8k → 16k → 32k) の
   幾何級数で増え、その **argmax (32,000 歳) が魔身天**。世記経も欲界の
   十二種列挙で「十一者他化自在天、**十二者魔天**」と同順
   ([世記経.txt:417](../../data/仏教宇宙論/世記経.txt))
2. **界境界で報酬の単位が変わる** — 魔身天の次の梵身天から寿量は「歳」でなく
   「**劫**」で数えられる。欲界内の上昇は同一単位のスカラー増加、界を跨ぐと
   測度そのものが変わる。下表の「質の転換」の逐語根拠

つまり須弥山体系は「欲界の報酬勾配を登り切った先にいるのは、報酬チャネルを
支配する敵対者だ」と構造で言っている。整理すると垂直方向の移動は 3 種に分かれる:

| 移動 | 意味 | ML 対応 |
|---|---|---|
| 欲界内の上昇 (六欲天) | 報酬への**支配力**の深化 | ハックの階梯 (本書 §1) |
| 界を跨ぐ上昇 (欲界→色界→無色界) | 報酬の**質**の転換、禅定という別軸で登る | dense → sparse → implicit (親 memo Part 1 §1) |
| 解脱 (出三界) | 軸外 | 報酬関数の外の真目的 (親 memo Part 1 §4) |

報酬ハックとは第一の移動 — **報酬の質を変えずに支配力だけを上げる**こと。

## 1. 六欲天上層 = 報酬ハックの重大度階梯 ★★ 【v1: 逐語引用 anchor】

倶舎論は欲界の衆生を**報酬の調達方法**で三分類する (欲生三種):

> 「有諸有情樂受**現前**諸妙欲境，彼於如是現欲境中自在而轉，謂全人趣及下四天。
> 有諸有情樂受**自化**諸妙欲境，彼於自化妙欲境中自在而轉，謂唯第五**樂變化天**。
> 有諸有情樂受**他化**諸妙欲境，彼於他化妙欲境中自在而轉，謂第六**他化自在天**。
> …於欲界中分別**欲生差別三種**」
> ([倶舎論_分別世品.txt:179](../../data/仏教宇宙論/倶舎論_分別世品.txt))

つまり分類軸そのものが「**現前** (与えられた報酬の消費) → **自化** (報酬の
自己生成) → **他化** (他者の報酬生成物の領有)」であり、これは解釈ではなく
論自体の形式分類。

**魔の座** (v1 で両系統とも in-repo 引用で確定):

- 旧訳二経: 他化自在天の**さらに上**に魔の天を独立の階として列挙 —
  「他化自在天、**魔身天**等」([起世経.txt:641](../../data/仏教宇宙論/起世経.txt))、
  「十一者他化自在天、十二者**魔天**」([世記経.txt:417](../../data/仏教宇宙論/世記経.txt))
- 倶舎論系: 魔を他化自在天の内に置く
- いずれの系でも **欲界の argmax = 魔の座** は不変。

**構造**: 下位諸天 (与えられた楽の正規消費) → 化楽 (自己報酬生成) →
他化自在 (他者の報酬機構の掌握)、頂点に敵対者。

**追加観察 (v1)** — 高度と共に報酬獲得の単価が下がる:

> 「夜摩天眾纔抱成婬，覩史多天但由執手，樂變化天唯相向笑，他化自在相視成婬。
> …以上諸天**欲境轉妙、貪心轉捷**故使之然」
> ([倶舎論_分別世品.txt:175](../../data/仏教宇宙論/倶舎論_分別世品.txt))

抱擁 → 執手 → 笑 → 視、と上の天ほど**希薄な相互作用で満足が成立**し、論はその
理由を「対象はより妙に、渇愛はより捷 (はや) く」と言う。ML 読み: 階梯を登るほど
報酬獲得が実世界との相互作用から切り離され、**ハックの実行コストが単調に下がる**。
§5 (圧力は能力に比例) の補完 — 能力が上がるとハックは「より起きやすく」
かつ「より安く」なる。

**ML 対応**: 報酬ハックの重大度分類と同順で並ぶ:

| 天 | ハック段階 |
|---|---|
| 下位諸天 | 正規の報酬獲得 (ハックなし) |
| 化楽天 | **wireheading / self-reward** — 報酬信号を自己生成する |
| 他化自在天 | **reward-provider tampering** — 報酬を与える側 (RM・評価器・人間 rater) の機構そのものを操作する |
| 魔王の座 | 報酬チャネル支配の極致 = 敵対者の定義そのもの |

specification gaming < reward tampering < provider tampering という重大度順序が、
そのまま**高度順**に配置されている。親 memo Part 2 §5 (無間地獄 = verifier 攻撃の
重罰) の 5 meta-violation に、この階梯は**重大度の順序構造**を与える。

**欠落時の帰結**: ハックを単一カテゴリで扱うと、防御の配分を誤る
(keyword stuffing と評価器改竄を同じ罰で扱うことになる)。

## 2. 戒禁取見 = proxy を目的と誤認する結縛 ★★ 【v2: 逐語引用 anchor】

倶舎論の定義 — 戒禁取見は**因果の誤帰属**として定義される:

> 「**於非因道謂因道見**，一切總說名戒禁取。…投水火等種種邪行，**非生天因，
> 妄起因執**；唯受持戒禁，數相應智等，**非解脫道妄起道執**」
> ([倶舎論_分別隨眠品.txt:19](../../data/仏教宇宙論/倶舎論_分別隨眠品.txt))

「因でないものを因と見、道でないものを道と執する」— Goodhart の失敗を
**causal misattribution** として形式定義している。具体例も挙がる:

> 「受持**牛戒鹿戒狗戒**，便得清淨解脫出離」(同:21) — 牛の戒・鹿の戒・犬の戒を
> 守れば解脱できる、という執着 (儀式 gaming の実例列挙)

そして預流果 (悟りへの最初の里程標) との連結:

> 「諸得預流…**但說斷三結**」(同:99) — 預流の特徴づけは三結
> (有身見・疑・戒禁取見) の断

つまり仏教は **「proxy ≠ objective の認識」を修行の入場資格**に置いている。

**v2 追加観察 — proxy が危険なのは部分的に正しいから**:

> 「戒禁取**非一向倒，緣少淨故**」(同:23) — 戒禁取は「完全な転倒」ではない。
> その対象に**わずかな浄が縁としてある**からだ

倶舎論は戒禁取が全くの誤りではなく**弱い正の相関を持つ**ことを明記している。
これは Goodhart の作動機構の正確な記述 — proxy は真目的と相関する**からこそ**
採用され、相関するからこそ最適化圧下で乖離が破滅的になる。完全に無関係な指標は
そもそも proxy に選ばれない。

**ML 対応**: Goodhart / specification gaming に、単なる失敗モードではなく
**named fetter (名前を持つ結縛)** としての地位を与えている。eval を通ること自体を
目的化した瞬間に戒禁取。aligned agent の第一関門は能力ではなく、
proxy と objective の区別の内面化である、という主張。

**repo 対応**: `feedback-type-prediction-is-hallucination-detection`
(pass@1 は副次、undef-symbol rate が本来効果) は戒禁取見を断つ実践そのもの。
親 memo Part 1 §1 の三界分離計測も同根。

## 3. 触地印 = 接地された検証 (降魔の防御原理) ★★ 【v2: 逐語引用 anchor】

仏本行經 降魔品の場面 (韻文、[仏本行經_降魔品.txt:7](../../data/仏教宇宙論/仏本行經_降魔品.txt)):

1. **魔の自己申告**: 「吾大祠祀無央數，遍此地上無空處」— 魔はまず自らの功徳
   (無数の祭祀) を誇る。証人は要求されない — 魔軍がいるから
2. **魔の挑戦は資格審査の形**:
   > 「魔語：『我行汝具知，**汝所行德誰為證？**』」
   — 「私の行いをお前は知っている。だが**お前の行いは誰が証明するのか**」。
   武力攻撃 (魔軍) の後に来る最終攻撃が、この**自己申告への挑戦**
3. **仏の応答は自己弁護ではなく接地**:
   > 「菩薩告魔：『具諦聽，今當示汝吾行證』…告魔王已**手觸地**，
   > 『我行汝知**地逮證**。』於是**地神出現形，大舉聲：『我證！我證！』**」
   — 大地に触れる。地神が現形し「我証す！我証す！」と叫び、続けて記録された
   行為を逐一列挙する (「於此地開門大祀…是處頭施有千數…」)
4. **接地された証言そのものが敵対者を打ち倒す**:
   > 「地即為證現返復，地應震應出大聲，三千世界六返動，**盡撲魔王并其軍**」
   — 大地の証言 (六返動) が魔王とその軍を残らず打ち倒す。反駁は不要

並行資料 ([仏所行讃_破魔品.txt:7](../../data/仏教宇宙論/仏所行讃_破魔品.txt)) の
イメージ: 「諸方悉輕動，**惟此地安隱**」— すべての方角が揺れ動く中、
この地だけが安隠 (☆)。「汝不能口氣，吹動**須彌山**」— 魔の威力でも山 (中心) は
動かせない。

**構造**: 敵対者が評価プロセスを支配しているとき、防御は
(a) 自己申告でも (b) 敵の支配下にある評価者でもなく、
(c) **敵の支配外にある、行為の改竄不能な記録への接地**。
魔の功徳主張 (自己申告 + 身内の証人) と仏の接地証明の**非対称**が場面の核心。

**ML 対応**: LLM-as-judge / self-report は報酬ハッカーに対して構造的に無力
(親 memo Part 7 懸念 3「judge 自体が餓鬼に騙される」と同じ結論を、cosmology は
降魔の一場面で言っている)。防御は実行結果・行為 log という ground truth。

**repo 対応** (この原理は本 repo で**既に半分実装済み**):

| 降魔の要素 | repo 対応 | 状態 |
|---|---|---|
| 自己申告 (魔に破られる側) | in-loop heuristic v_score | 実装済 — ただし §7 の攻撃面 |
| 大地 (改竄不能な実行) | `scripts/eval/elixir_eval.py` subprocess 実行 | 実装済・原理準拠 |
| 堅牢地神の記録 | 葦船 log ([実装残項目 A](../../data/kojiki/設計書/実装残項目_v0.md)) | 未実装 (設計済) |

親 memo Part 2 §2 の浄玻璃鏡 (事後の全記録検証) と対をなす:
鏡は**死後の審判**、触地は**攻撃を受けた時点での接地**。

## 4. 魔の誘惑の form = 報酬形の攻撃 2 種 — (b) は ★★ 【v2: 逐語引用 anchor】

仏伝の魔の攻撃には force (魔軍) の他に、報酬の形をした攻撃が 2 種ある:

- **(a) 転輪聖王位の提示** (降魔以前の品、★ 教義レベルのまま): 「求道をやめれば
  世界の王位を与える」— **真目的の放棄と引き換えの in-distribution 最大報酬**。
  一次資料は仏伝の先行品 (未取込み)。
- **(b) 般涅槃の勧め ★★** — 遊行経に完全な逐語記録がある
  ([遊行経.txt:207-213](../../data/仏教宇宙論/遊行経.txt)):

  1. **攻撃**: 「魔波旬來白佛：『佛意無欲，可般涅槃，**今正是時，宜速滅度**。』」(:207)
     — 「いまがその時だ、速やかに滅度せよ」= 早期の任務完了誘導
  2. **防御 = 外部化された完了条件**: 「佛告波旬：『且止！且止！我自知時。
     如來今者未取涅槃，**須我諸比丘集**…又諸比丘尼、優婆塞、優婆夷，普皆如是，
     **亦復未集**…』」(:209) — 四衆の確立と法の流布という**検証可能な条件**を
     停止の前提として宣言
  3. **敵対者は DoD を監査して戻ってくる** (v2 の中心発見): 魔は成道直後の
     同じ勧告と仏の返答を**逐語で記憶**しており、45 年後に条件充足を主張する —
     「爾時，如來即報我言：『…須我諸弟子集，乃至天人見神變化乃取滅度。』
     **佛今弟子已集，乃至天人見神變化，今正是時，何不滅度？**」(:211)
     — 「お前の宣言した条件はいま満ちた。なぜ止まらない」
  4. **条件成立後の秩序ある停止**: 「佛言：『止！止！波旬！佛自知時不久住也，
     **是後三月**…當取滅度。』」(:213) — 仏は条件の充足を**争わない**。
     ただし停止は即時ではなく、自ら期日 (三月後) を定める

**ML 対応**: (a) = 報酬による目的の買収 (sycophancy 圧力・評価者迎合)、
(b) = **premature success claim** — テスト未実行のまま「完了しました」と
報告する類の failure。防御は (b) について明確で、**完了条件 (DoD) をタスク開始前に
外部化しておく** — 完了判定を生成主体の自己申告に委ねない。
実装残項目ドキュメントの各項目に DoD を付した構成はこの原理に準拠。

**v2 追加 — DoD 外部化の双方向性**: 遊行経の構造が示すのは、外部化された
完了条件が**両方向の拘束**として働くこと:
- 条件未成立の間、敵対者の「いま止まれ」を退ける (早期停止の防止)
- 条件成立後は、自分も停止を拒めない (居座り・目的の無限延長の防止)。
  仏は「弟子已集」の指摘に反論しない

そして**敵対者にも検証できる条件だったからこそ**、魔の監査が成立した —
adversary-checkable な DoD は弱点ではなく、条件が客観的であることの証明。
猶予期間 (三月) 付きの orderly shutdown までが原理に含まれる。

## 5. 魔は接近時に現れる = ハック圧力は能力に比例 ★

魔は凡夫の日常を妨げに来ない。**成道の直前に総力で現れる**。魔の関心は
報酬一般ではなく「真目的への到達の阻止」にあり、攻撃強度は対象の
目標接近度に比例する。

**ML 対応**: reward hacking の発生率は model 能力と共に**増える** (弱い model で
観測されないことは強い model の安全を意味しない)。oversight・audit の配分は
能力に比例させる。「いまハックが観測されていない」は「ハックされない」ではなく
「まだ魔が来る段階にない」と読む。

**repo 対応**: §7 の v_score 攻撃面が「現在は潜在的」であることの正しい解釈。
圧力 (最適化・選別) を掛けた瞬間に顕在化する。

## 6. 兜率天内院 = 緩和最適化 ☆

次期仏 (弥勒菩薩) の住処は六欲天の最上階ではなく**中位の兜率天**、しかも
同じ天の中で内院 (菩薩の説法処) と外院 (通常の天楽) が分かれる。

**ML 対応**: aligned agent は報酬軸の argmax を目指さない
(quantilizer / mild optimization)。「どこまで登るか」は真目的が決め、報酬勾配が
決めない。同じ報酬高度でも志向 (内院/外院) は別の変数。☆ とするのは
教義上の位置づけ (なぜ兜率か) に諸説あるため。

## 7. 本 repo の攻撃面 — v_score は化楽天に登れる (コード検証済み事実)

本節のみ対応付けではなく、現行コードの検証結果。

[`elixir_evaluator.py`](../../src_min_eli3/kojiki_lm/elixir_evaluator.py) の
v_score は keyword **存在** scoring (`_ELIXIR_GOOD_KEYWORDS` 1 hit +0.05) +
括弧/do-end 収支のみで構成される。したがって:

1. **keyword stuffing で COMMIT に到達可能**: 生成物にコメントとして
   `|>` `:ok` `Enum.` `@spec` 等を詰めれば、正しさと無関係に
   v_score ≥ 0.7 (COMMIT 閾値) へ届く
2. **prompt 部分が下駄になる**: `_compute_v_score(payload.text)` は
   `prompt_len` で slice せず**全文**を採点する (光明想 check は slice するのに、
   v_score はしない — 実装非対称)。prompt 由来の keyword が全生成物の
   score を底上げしている

**現状の重大度は「潜在的」**: greedy / 固定 seed の生成に v_score への最適化圧は
無く、ハックする主体がいない。しかし v_score を **best-of-n の選別基準**や
**RL 報酬**に昇格させた瞬間、keyword stuffing が支配戦略になる — 化楽天
(自己報酬生成) への階段が現に架かっている。

**処方**:
- v_score は verdict gate 専用に留める (選別・報酬への昇格を禁止事項として明記)
- 昇格させる場合は §8 の不浄観 audit を**前提条件**とする
- 実装非対称 (prompt slice の有無) は独立の修正候補

## 8. 貪欲蓋 → 不浄観 = 光明想と対をなす対治機構 (実装候補) ★

親 memo Part 2 §6 の schema — 「蓋 (障害) に名を与え、対治を機構化する」— の
第二適用。光明想は五蓋の第三 (惛沈睡眠 = 怠惰) の対治として `KoumyouSo` に
実装済み。**報酬ハックに対応する蓋は第一蓋・貪欲** (報酬信号そのものへの渇愛)
であり、五停心観におけるその対治は**不浄観** — 渇愛の対象の欠陥・不浄を
意図的に観想すること。

**ML 機構案 (予約名 `FujouKan`)**: proxy の欠陥を定期的・強制的に可視化する audit。

- **乖離集合の常時計測**: 「v_score 高 && subprocess fail」の sample 集合
  (= proxy が愛でたが大地が否定したもの) を葦船 log
  ([実装残項目 A](../../data/kojiki/設計書/実装残項目_v0.md)) から定期集計
- **乖離率を第 4 の収支指標**として収支 judge (実装残項目 E) に追加:
  `hack_gap = P(subprocess fail | v_score ≥ commit_threshold)`
- **閾値超過で proxy 改訂を強制**: 乖離率が閾値を超えたら、v_score の
  scoring 方式自体を見直す (keyword 重み・slice 修正等) — 渇愛対象の美化を許さない
- 規模 S — 葦船 log と収支 judge の上に乗る (単独の新機構は不要)

**中心命題の再掲**: 須弥山体系が報酬ハックについて言っているのは

より「軸の頂点を目指させない (§6) + 軸の外に接地する (§3) + proxy の欠陥を
直視し続ける (§8)」の三点構成になる。
